# 简历与面试材料

## 项目描述

**KnowTrace：可追溯文档检索与可选生成问答工作台。** 面向本地PDF/Markdown/TXT/DOCX文档，实现权限范围内的检索、原文引用、证据不足拒答、可复跑评测，以及显式启用的模型适配路径。

## 可以按事实写的简历内容

- 使用FastAPI与SQLite构建本地文档应用，支持四类文档导入、内容去重、物理页/逻辑行溯源和知识库权限隔离；在排名前过滤授权语料，并对原文件访问实施同一权限检查。
- 实现BM25、字符TF-IDF与RRF融合检索，分析中文分词和未知词对证据门槛的影响；分离检索候选与实际采用引用，保留开发集实验及回归比较。
- 固定20篇官方文档及SHA，构建100题AI辅助、来源核对的评测草稿；输出Recall、MRR、误拒答、无答案接受、实际来源采用和本地延迟报告。
- 编写Ollama与Chat Completions兼容适配器，校验结构化输出和引用ID；通过模拟服务验证异常分支，并用DeepSeek完成合成资料真实联调。此小样本不代表生成质量基准或生产上线。
- 接入固定版本的本地E5 ONNX语义向量，与词法排序做RRF比较；实现ACL过滤后的SQLite向量缓存和级联删除，发现并修正动态INT8批次对文档向量的影响，以单段推理和模型指纹保障缓存隔离。

具体分数和测试数量以当前 `VALIDATION.md` 为准，确认后再填简历。无实证的并发量、用户规模、节省成本和生产上线都不填写。此项目属于AI辅助完成的个人作品，需要亲自理解和复现后再用于面试。

## 三分钟演示顺序

1. **问题与边界**：展示离线默认状态，说明此时是原文摘录。
2. **证据问答**：用“路径参数”检索，点开引用核对标题与行号，切换BM25/混合模式观察差异。
3. **权限**：工程账号只能看到工程知识库；切换支持账号后资料、回答、来源与评测一并清空重载。
4. **不足与候选**：提一个现有语料没有答案的问题，展示明确拒答和“未验证候选”；解释候选相似不代表支持结论。
5. **可复验**：运行测试分组评测，查看逐题失败和前后对比。指出误拒答、无答案误接收的权衡。
6. **可选模型**：说明两种适配协议和引用格式校验。DeepSeek已完成一次合成资料真实联调，可展示[验收记录](DEEPSEEK_VALIDATION.md)；现场选择“模型回答”才请求新的推理，默认仍是离线摘录。一次联调不代表广泛生成质量评测。

短版实际静音演示见 `media/offline-demo.webm`，仅展示离线模式。重新录制需Playwright版本匹配的ffmpeg辅助程序（可用 `npx playwright install ffmpeg` 安装）；本轮复用了本机已有编码器，运行时二进制不随源码分发。

## 面试追问与可核对答案

**为什么不是直接把全部文件塞进模型？**
权限、上下文长度、成本和可追溯性需要明确控制。这里先授权再召回，来源定位在解析阶段保留。当前没有做大规模吞吐验证。

**BM25和字符TF-IDF分别有什么用？**
BM25侧重词项频率和长度归一化；字符n-gram更能处理部分词形和字符串重叠。RRF融合名次而非直接相加异量纲分数。它们仍是词法方法，不能当语义向量模型。

**如何证明降低误拒答没有引入乱答？**
同时检查可答题误拒答、无答案接受率和预期来源实际采用率，并保留独立反例。即使这些指标改善，也不证明语义正确，仍需要人工标注与后续生成质量评估。

**权限过滤为什么放在排名前？**
若只在返回前删私有片段，私有语料还会影响IDF、排序、延迟和结果数量。当前索引按授权范围缓存，文件下载和删除也重新校验权限。

**有引用就等于不幻觉吗？**
不等于。引用ID和标记核验只能检查模型引用了允许的片段，无法证明每句话受片段支持。需要后续做句子级核验、人工评审和冲突测试。

**结果能代表生产效果吗？**
不能。100题为AI辅助且未独立人工复核的草稿，dev/test共享文档；test已被查看，复验只能算回归。延迟是小语料、本机、预热顺序运行。

## 后续应亲自完成的练习

用一组自己熟悉、可公开的小文档替换演示语料；人工标注一批新问题；独立跑评测并解释两个真实失败例。对已接入的个人API补真实生成评审；理解语义排序和证据准入为何分开，以及为何保留词法默认模式。
